# Genshin Impact Gacha Analytics

Turn your [Paimon.moe](https://paimon.moe) wish-history export into analytics, an interactive dashboard, and an auto-updating Google Sheet.

**Live demo:** [history-gi-noviardhana.streamlit.app](https://history-gi-noviardhana.streamlit.app/)

## Overview

```
Paimon.moe export (JSON)
        │
        ▼
00_fetch_rarity_lookup.py    item name / rarity lookup
        │
        ▼
01_preprocessing.py          export + lookup → data/data_clean.csv
        │
        ├──► 02_analytics.py      7 insights (CSV + PNG) → outputs/
        ├──► 03_dashboard.py      interactive Streamlit dashboard
        └──► 04_sync_gsheet.py    (optional) Google Sheets, one tab per account
```

## Features

**Analytics**
- Total pulls and account progress (rarity, Adventure Rank, World Level)
- Monthly wish timeline by banner
- 5★ pity distribution and 50/50 win rate per banner
- Top characters and weapons, banner performance, composite luck score

**Dashboard**
- Sections: Overview → Banner Pity Meters → Summary → Detailed Analysis (9 tabs)
- Date and banner filters apply to the whole page; single, compare, or all-accounts mode
- Pity meters with one tab per account, plus per-tab account filters
- Latest 5★ and Pull History tables (History filterable by banner and type)
- A one-line commentary under every chart, and CSV export

**Google Sheets sync (optional)**
- One tab per account with Character / Weapon / Standard tables
- Each table lists pity and 50/50 result; current pity shown above it
- Never deletes existing data

**Automation**
- GitHub Actions regenerates everything (and the Sheet) when a new export is pushed

## Quick Start

```bash
pip install -r requirements.txt
```

1. Export your data from [paimon.moe](https://paimon.moe): **Wish Counter → Export Data**.
2. Save it as `data/paimon-moe-local-data.json`.
3. Run:

```bash
python3 00_fetch_rarity_lookup.py   # once, or to refresh after new releases
python3 01_preprocessing.py
streamlit run 03_dashboard.py
```

Requires Python 3.9+. On Windows use `python` or `py` instead of `python3`.

## Usage

| Step | Command | Output |
|---|---|---|
| 00 | `python3 00_fetch_rarity_lookup.py` | `data/char_full.json`, `data/weapon_full.json` |
| 01 | `python3 01_preprocessing.py` | `data/data_clean.csv` |
| 02 | `python3 02_analytics.py` | `outputs/01_…` to `07_…` (CSV + PNG) |
| 03 | `streamlit run 03_dashboard.py` | dashboard at `http://localhost:8501` |
| 04 | `python3 04_sync_gsheet.py --preprocess` | Google Sheet (optional) |

**Notes**
- **00:** reads Paimon.moe's GitHub source (needs access to `raw.githubusercontent.com`). The export holds only item IDs, time, type and pity, so names and rarity come from this lookup.
- **01:** the export already contains your full history, so re-running it rebuilds `data_clean.csv` from scratch. Options: `--list-uid`, `--uid <uid>` (single account → `data_clean_<uid>.csv`).
- **02:** options `--input <csv>`, `--outdir <folder>`.
- **03:** use `-- --data <csv>` to open a specific file, e.g. `streamlit run 03_dashboard.py -- --data data/data_clean_887284572.csv`.

## Google Sheets Sync

Writes `data_clean.csv` to a Google Sheet: one tab per account, with three tables side by side (Character Event, Weapon Event, Standard) listing 4★/5★ pulls — date, name, rarity, pity, 50/50 result.

**One-time setup**
1. Create a Google Sheet and copy its ID (the part of the URL between `/d/` and `/edit`).
2. In [Google Cloud Console](https://console.cloud.google.com), create a project and enable the **Google Sheets API**.
3. Create a **service account**, then add a **JSON key** to it (Keys → Add key).
4. Share the Sheet with the service account's `client_email` as **Editor**.
5. Create `credentials/secret.toml` (git-ignored):

```toml
[gsheet]
spreadsheet_id = "<sheet id>"

[gcp_service_account]
type = "service_account"
project_id = "<project id>"
private_key_id = "<from the JSON key>"
private_key = "-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
client_email = "<name>@<project>.iam.gserviceaccount.com"
token_uri = "https://oauth2.googleapis.com/token"
```

**Run**

```bash
python3 04_sync_gsheet.py --preprocess   # JSON → CSV → Sheet
python3 04_sync_gsheet.py                # CSV → Sheet
python3 04_sync_gsheet.py --dry-run      # preview only, no Google access
```

| Option | Effect |
|---|---|
| `--include-3star` | also list 3★ pulls (default: 4★ and 5★ only) |
| `--force` | overwrite a tab even if the new data has fewer pulls |
| `--sheet-id`, `--creds`, `--secrets`, `--csv` | override sheet id, key file, `secret.toml` path, CSV path |

**Safety:** tabs of accounts missing from the CSV are left untouched, and a tab is skipped with a warning if the new export has fewer pulls than the sheet already shows. The Beginners banner is not included.

## Automation (GitHub Actions)

`.github/workflows/cml.yml` runs on every push that changes `data/paimon-moe-local-data.json` or the workflow file, and manually via **Actions → Run workflow**.

**Pipeline:** fetch lookup → check export exists → preprocess → sync Google Sheets (if secrets are set) → analytics → dashboard smoke test → commit `data/` and `outputs/` back to `main` → post a report as a commit comment.

**Optional repository secrets** (*Settings → Secrets and variables → Actions*):

| Secret | Value |
|---|---|
| `GSHEET_ID` | the Google Sheet ID |
| `GCP_SERVICE_ACCOUNT_JSON` | the entire service-account JSON key file |

Without them the sync step is skipped with a notice. The step uses `continue-on-error`, so a Google/API problem never blocks the data commit.

**Updating your data**

```bash
git pull --rebase origin main    # the bot commits to main after each run
# replace data/paimon-moe-local-data.json with the new export
git add data/paimon-moe-local-data.json
git commit -m "update wish data"
git push
```

## Security

- Never commit the service-account key. `credentials/` and common key filenames are in `.gitignore`.
- The export and CSV contain your UIDs. Make sure that is acceptable for the repository's visibility.
- If a key is ever exposed, delete it in Google Cloud (Service Accounts → Keys) and create a new one.

## Troubleshooting

| Issue | Fix |
|---|---|
| `FileNotFoundError` for rarity lookup | Run `00_fetch_rarity_lookup.py` before `01_preprocessing.py`. |
| `[WARN] N row(s) have no rarity mapping` | New character/weapon not in the lookup yet. Re-run `00`, then `01`. |
| Connection error in `00_fetch_rarity_lookup.py` | Check access to `raw.githubusercontent.com` (proxy/firewall). |
| Dashboard can't find data | Make sure `data/data_clean.csv` exists (run `01`), or pass `-- --data <path>`. |
| `git push` rejected (non-fast-forward) | The CI bot committed after your last pull. Run `git pull --rebase origin main`, then push. |
| `credentials/` shows up in `git status` | `.gitignore` is missing the `credentials/` rule. It must be named `.gitignore` (with the leading dot). |
| `secret.toml: private_key is not a real key yet` | `private_key` is still a placeholder. Paste the full value from the JSON key (one line, keep the `\n`). |
| `403` / `PERMISSION_DENIED` / `SpreadsheetNotFound` | Share the Sheet with the service account's `client_email` as Editor, and enable the Google Sheets API. |
| Sync prints `[SKIP] '<tab>'` | Safety check: the new data has fewer pulls than the sheet. Export your full history again, or use `--force` if intended. |
| Streamlit Cloud install error | Avoid strict version pins in `requirements.txt`; pin Python via `runtime.txt`. |
| Streamlit Cloud: "You do not have access to this app" | Re-check the app's linked repo, or grant access at `github.com/settings/installations`. |

**Fixed**
- `03_dashboard.py`: the 4★ pity counter now resets only on a 4★ (previously a 5★ also reset it); pulls sharing a timestamp are ordered by CSV row order.
- `00_fetch_rarity_lookup.py`: name/rarity extraction no longer bleeds into neighbouring items.
